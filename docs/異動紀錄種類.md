# 異動紀錄種類清單（v2 — 語意事件制）

> 設計原則：異動紀錄是**給人看的時間軸**，不是 DB 操作 log。
> 每筆紀錄是一個「語意事件」（如「加入組別」），而不是 CRUD（如「update student: group_id」）。
> 技術層級的原始操作另存一張 `db_logs` 表（見第三節），主畫面不顯示。

### 帳號

> 不出現在異動紀錄主畫面（畫面只有 學生/老師/組別 三欄，帳號塞不進去也不該混在一起）。

## 二、資料表設計

### audit_logs（改版）——給人看的事件

| 欄位 | 說明 |
|------|------|
| id, created_at, actor | 同現行 |
| event | 事件 key（如 `student_join`），取代現行 action+entity |
| summary | 人話描述（含 改前→改後） |
| student_id | 關聯學生（nullable）→ 前端「學生」欄直接用 |
| teacher_id | 關聯老師（nullable）→ 前端「老師」欄 |
| group_id | 關聯組別（nullable）→ 前端「組別」欄 |

> 好處：一個事件可同時關聯多個對象（如「設定組長」同時掛 組別＋學生），前端三欄不用再從 entity 反查猜。

### db_logs（新增）——技術紀錄，僅除錯／稽核用

| 欄位 | 說明 |
|------|------|
| id, created_at, actor | 同上 |
| method | create / update / delete / import |
| table_name | students / groups / teachers / accounts / reviews / review_scores |
| record_id | 異動的紀錄 id |
| payload | JSON：改了哪些欄位、改前改後值 |

> 所有 API 寫入動作照實記錄（包含被主畫面排除的帳號、刪除等），不做翻譯。主畫面不讀這張表。
