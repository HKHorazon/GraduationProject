## 一、前端 AuditLogView.vue

### F1. 關聯欄位查不到時顯示「—」，不再顯示內部 id
- **問題**：學生/老師/組別欄查不到對應資料時（已刪除、或 store 還沒載完），直接把內部 id（`s01`、`t6`）顯示給使用者，看起來像壞資料。
- **修復**：`studentOf / teacherOf / groupOf` 查不到一律回 `null` → 畫面顯示「—」；名稱資訊本來就在「描述」欄，不會遺失。
- **回復**：把三個函式的 `: null` / `?? null` 改回傳 `l.student_id` 等原始 id。

### F2. 明確向後端要滿額資料（`?limit=500`）
- **問題**：後端 `GET /audit-logs` 預設只回 200 筆（上限 500）。前端做了分頁卻只拿得到 200 筆，總筆數會默默少報。
- **修復**：`loadLogs()` 改打 `/audit-logs?limit=500`。
- **回復**：改回 `api.get('/audit-logs')`。
- **已知限制**：超過 500 筆後仍會被截斷；屆時應改成後端分頁（`offset/limit` 或游標），此次未動後端。

### F3. 筆數顯示區分「符合 / 全部」
- **問題**：標題下方「共 N 筆」在搜尋時顯示的是過濾後筆數，語意誤導。
- **修復**：無關鍵字顯示「共 N 筆」；搜尋中顯示「符合 M 筆 / 共 N 筆」。
- **回復**：改回單一 `共 {{ filteredLogs.length }} 筆`。

### F4. 分頁列固定顯示，搜尋時版面不跳動
- **問題**：原本「只有超過一頁才顯示分頁列」——搜尋把結果濾到一頁以內時整條列消失，表格高度跳動（違反「表格格式不因搜尋而變化」的要求）。
- **修復**：分頁列永遠顯示，左側改為「顯示第 X–Y 筆 · 第 P / T 頁」（無結果時顯示「0 筆」），單頁時上一頁/下一頁自動停用。
- **回復**：在分頁列外層 div 加回 `v-if="totalPages > 1"`。

### F5. 欄寬微調（配合 v2 事件名稱）
- **問題**：「操作」欄 `w-28`（112px）放不下新的六字事件「修改指導老師」；表格是 `table-fixed`，過窄會被裁切。
- **修復**：操作者 `w-28 → w-24`、操作 `w-28 → w-32`。
- **回復**：兩個 th 的 class 改回 `w-28`。

> 註：表格 `table-fixed` 固定欄寬、全域搜尋、50 筆分頁本體，是本日稍早依需求所做的功能，非本次修復項目，不在此列。
> v2 事件對照表（`EVENT_META`）與 `student_id/teacher_id/group_id` 直接關聯欄位為同日的 schema 改版內容，本次僅檢查確認與 `docs/異動紀錄種類.md` 一致。

## 二、Mock 種子 backend/seed_audit.py

### S1. 時間產生方式修正（時區與半夜時間）
- **問題**：原 `dt()` 以 **UTC** 取時 — 寫 `hour=9` 前端顯示成 17:00（台灣 +8）；搭配小數天數會再偏移，產生半夜 02:00 的異動紀錄，不符合「老師上班時間操作」的常理。
- **修復**：`dt()` 改用**本地時區**（`datetime.now().astimezone()`）+ 整數天數；種子裡寫的 hour:minute 就是前端顯示的時間。
- **回復**：`base = datetime.now(timezone.utc).replace(...)`（並把 `timezone` 加回 import）。

### S2. 補齊 112 學年後半名單
- **問題**：DB 有 112 學年學生 12 人（s13–s24）與 4 組（g5–g8），種子只記了 6 人、2 個組長 — 時間軸殘缺。
- **修復**：補 s19–s24 新增、s19–s23 加入 g7/g8、g7 組長盧冠廷（s19）、g8 組長倪靜怡（s22）——組長與 DB `leader_id` 一致。
- **回復**：刪除新加的 13 行（s19–s24 區段與 g7/g8 的 join/leader 行）。

### S3. 重複時間戳分散
- **問題**：同學年 12 筆「新增學生」全是同一分鐘（`dt(60,10,0)`×6、`dt(30,9,0)`×12），排序只能靠 id，看起來像複製貼上。
- **修復**：每筆遞增 1 分鐘。
- **回復**：把分鐘改回 0。

### S4. g3 類別異動方向修正
- **問題**：種子寫「類別：人工智慧 → 多媒體」，但 DB 現況 g3 類別是**人工智慧** — 紀錄的「改完結果」與現實矛盾。
- **修復**：改為「多媒體 → 人工智慧」。
- **回復**：對調兩個詞。

### S5. 不存在的老師「林志明」
- **問題**：「第2組 指導老師：林志明 → …」— 老師表只有 陳志明(t1)/林美華(t2)/黃建國(t3)/劉雅婷(t4)/張文傑(t5)，「林志明」是混名。
- **修復**：改為「林美華」。
- **回復**：改回原字串。

### S6. 韓梅（t6）生命週期一致化
- **問題**：種子記「新增老師 韓梅(t6)」但 teachers 表沒有 t6，畫面上像資料壞掉。
- **修復**：依 v2 設計（刪除老師**不進**異動紀錄、只記 db_logs），在 `main()` 補種一筆 db_logs：`delete teachers t6`。異動紀錄兩筆韓梅事件的「老師」欄顯示「—」即屬正常（人已刪除）。
- **回復**：刪除 `main()` 裡 DbLog 區塊；並自行決定是否把兩筆韓梅事件一併刪除。

### S7. 結尾事件對齊 DB 現況（g9 / s12 / g4 組長）
- **問題**：種子最後寫「周靜文加入第4組」「第4組組長：蔡宗翰」，但 DB 現況是：s12 在 **g9**、g4 組長是 **s10 許美玲**、s03/s11 也在 g9、g9 是 114 學年第 3 組「DDDD」（leader s03）。
- **修復**：改寫結尾為一段與 DB 收斂一致的故事：
  - 建立 第3組「校園活動報名系統」（114學年）→ 改題目為「DDDD」
  - 張偉豪 s03：第1組 → 第3組（114）；蔡宗翰 s11：第4組 → 第3組（114）；周靜文 s12 加入
  - 第3組（114）組長：張偉豪 — 與 `g9.leader_id = s03` 一致
- **回復**：把該區塊換回原兩行（不建議——會恢復矛盾）。

### S8. 大量填充資料（讓分頁看得到）
- **問題**：精選資料 77 筆不足兩頁，無法驗證 50 筆/頁分頁。
- **修復**：新增 `bulk_logs()`：產生 24 對（48 筆）「改了又改回來」的成對事件（換組又換回、改題又改回、改類別又改回），**成對自我抵銷**所以最終狀態仍與 DB 一致；固定亂數種子（42）可重現；時間限制在 day 5–27 的上班時段，避開組別建立（day 30）與 g9 異動（day ≤3）。總計 **125 筆 → 3 頁（50/50/25）**。
- **回復／關閉**：把 `BULK_PAIRS = 24` 改為 `0`（保留程式）或整段刪除。

### S9. 重種策略
- **行為**：筆數已達目標 → 跳過；不足 → **清空 audit_logs 重種**。
- ⚠ 清空會連同真實操作產生的紀錄一起刪除，**僅適用本地開發 DB**；正式環境請勿執行此腳本（docstring 已註明）。
