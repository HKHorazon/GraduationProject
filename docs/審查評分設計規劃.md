# 審查評分 設計規劃

依 `docs/專題製作評分辦法.md`（第 7 條、附件四）實作的評分系統。頁面：側欄「審查 → 審查評分」(`/reviews`)。

## 規則

- 一次「審查」＝ 一個 `Review`（第一次企劃審查、第二次創意審查、第三次複審、第四次總審…），由 **super_admin** 建立與設定。
- **分數掛在組別**，不分學生（符合辦法「各專題製作小組期中成績」）。
- 每位評審對每一組留下**一列**分數：系上老師或外審委員。
- **系上老師不得評自己指導的組別** — 前端不列出該組，後端 `PUT/bulk` 也擋（含匯入）。
- **外審委員不屬於系上老師**：沒有帳號、沒有 Teacher 紀錄，成績由 super_admin 從 Excel 匯入。

## 資料表

### `reviews`

| 欄位 | 說明 |
|------|------|
| id | `rv{n}` |
| name | 審查名稱（第一次企劃審查…） |
| school_year | ROC 學年字串 |
| criteria | JSON `[{"name": ..., "weight": ...}]` |
| reviewers | JSON `['t1', '外:王大明']` — 這次審查的評審名單 |
| internal_weight | 系上老師平均的佔比（預設 60） |
| external_weight | 外審委員平均的佔比（預設 40） |
| is_open | 是否開放評分（關閉後只有 super_admin 能改） |
| created_at | |

`reviewers` 決定總覽／Excel 要出現哪些欄（含還沒評分的老師，所以缺誰一目了然）。名單只是預設值：
有名單外的評審寫入分數時後端會自動把他補進名單 —— 匯入不該被名單擋住。

一組的最終成績 = 系上老師平均 × `internal_weight` + 外審委員平均 × `external_weight`（除以兩者之和）。
**沒評分的評審不列入平均**（分母只算實際有分數的人）；只有一邊有成績時，總分就等於那一邊的平均。

`criteria` 同時涵蓋兩種評分顆粒度，**不需要 mode 欄位**：

- 單一總分 → `[{"name":"總分","weight":100}]`
- 六向度尺規（附件四）→ 六個項目，權重 15/10/25/20/15/15

總分一律是「各項分數依權重加權平均」，兩種模式共用同一條計算路徑。管理者也可自訂項目與權重。

### `review_scores`

| 欄位 | 說明 |
|------|------|
| id | 自增 |
| review_id / group_id | FK，`ondelete=CASCADE` |
| reviewer | `t3` = Teacher.id；`外:王大明` = 外審委員 |
| scores | JSON 數字陣列，順序對齊 `review.criteria` |
| comment | 評語（選填） |
| updated_at | |

唯一鍵 `(review_id, group_id, reviewer)` — 同一位評審對同一組只有一列，重複寫入即覆蓋（匯入才能無痛重跑）。

> `reviewer` 用一欄同時表示老師與外審委員，是為了讓唯一鍵在 Postgres 也成立（兩個 nullable 欄位會因為 `NULL != NULL` 讓唯一鍵失效）。外審委員的姓名就是識別；真的需要管理外審委員名單時再拆表。

## API（`backend/app/routers/reviews.py`）

| Method | Path | 權限 |
|--------|------|------|
| GET | `/reviews` | 無 |
| POST | `/reviews` | super_admin |
| PATCH | `/reviews/{id}` | super_admin |
| DELETE | `/reviews/{id}` | super_admin（連同評分一起刪） |
| GET | `/reviews/{id}/scores` | 無 |
| PUT | `/reviews/{id}/scores` | editor（upsert 單列） |
| POST | `/reviews/{id}/scores/bulk` | super_admin（Excel 匯入，整批 upsert） |
| DELETE | `/reviews/{id}/scores/{score_id}` | editor |

寫入共用檢查（`_check`）：項目數量相符 → 分數 0–100 → 組別存在 → 審查開放中（super_admin 例外）→ 一般老師只能寫自己那列（super_admin 可代填）→ 評審存在 → 不是自己指導的組。

`bulk` 任一列不合法就整批 400 退回，不會半匯入。

改 `criteria` 的**數量**在已有評分時會被擋（400），避免分數陣列跟項目對不齊。

稽核：只寫 `db_logs`，不進 `audit_logs`（見 `docs/異動紀錄種類.md`）。

## 前端（`frontend/src/views/ReviewsView.vue`）

審查的新增／設定**直接展開在頁面上**，不用彈窗。設定內容：名稱、學年、評分項目（單一總分／六向度只是預設按鈕，可自由增刪改權重）、
評審名單（系上老師勾選 + 外審委員打名字加入）、系上／外審比重、是否開放評分。

Excel 工具列常駐（成績主要靠匯入）：**下載範本／匯入成績**（super_admin）＋**匯出成績**（所有人）。

兩個分頁：

- **總覽** — 矩陣，版型與 Excel 完全一致（見下）。super_admin 點任一格可直接小修正（含刪除）。
- **我的評分** — 登入老師自己那一欄，逐項輸入、即時顯示加權總分、逐列儲存／清除。

### Excel／總覽版型（`frontend/src/lib/reviewSheet.js`）

```
row1: 組別 | 指導老師 | 陳老師（跨自己的項目欄） | … | 系上平均 | 外審平均 | 加權總分
row2:      |          |  項目A  |  項目B          | …
row3+: 一組一列
```

- 第一列是各評審，第一欄組別，第二欄指導老師，最後三欄是平均區。
- 單一總分的審查，第二列就只有「總分」一欄，版型自然退化成一人一欄。
- **自己指導的組別照樣列出來**，該格是紅底的「—」，匯入時整格跳過。
- 評審欄名對得上系上老師名單就是該老師，對不上就視為外審委員（匯出寫成「姓名（外審）」，匯入自動去後綴）。
- 平均欄是給人看的，匯入時忽略。

Excel 讀寫全在瀏覽器（`xlsx-js-style` — 社群版 `xlsx` 寫不出儲存格顏色，這是它的 drop-in fork，
專案內已全面換掉 `xlsx`），後端只吃 JSON，不需要 openpyxl。

版型的 build/parse 是純函式，有自我檢查：`cd frontend && node src/lib/test_reviewSheet.mjs`
（往返後分數不變、紅格不被匯入、空白範本不產生 0 分、壞資料擋下來）。

## 刻意沒做

- 外審委員登入／臨時帳號 — 成績從 Excel 進，外審不碰系統。
- 每位學生個別分數 — 辦法是組別成績；真要個別加減分再加一張 override 表。
- 跨審查的學期總成績加權（60%/40% 那層）— 先把單次審查做對，總成績等實際要出成績單時再說。
